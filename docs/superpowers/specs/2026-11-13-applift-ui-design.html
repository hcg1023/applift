applift-ui 全场景设计规格

版本 v1 · 2026-11-13 · 风格基准：Apple HIG（克制、留白、SF 排版气质、少边框多分组）· 浅色为主 + 深色模式 · 形态：一期 webui（applift ui localhost），二期 Tauri 壳

标注约定：MVP 必须 一期实现 · 二期 · 占位（只做布局预留，不细化）

0. 设计系统基线（token）

所有颜色经语义 token 引用（见本文件 <style> 的 :root / [data-theme="dark"]），组件层禁止裸色。

类别 token 浅色值 说明
画布/面板 bg-canvas / bg-primary / bg-secondary / bg-sidebar #F5F5F7 / #FFFFFF / #F9F9FB / #ECECF0 三层灰阶，靠留白与底色差分组，不画边框线
文字 label-primary / secondary / tertiary 黑 88% / 55% / 35% 三级字阶，禁再细
分隔 separator 黑 9% 仅分组间 hairline
品牌 accent #0A62FF（暗色 #4D95FF） 主操作、链接、进行中
状态 success / pending / rejected / stale / info 绿 / 琥珀 / 红 / 灰 / 蓝 语义唯一：跃迁成功、审核中、被拒/错误、旧数据、信息
排版 系统栈（-apple-system → PingFang SC）；正文 13–14px，标题 17/20/28px 三级；等宽 12.5px 用于版本号、路径、commit
圆角/阴影 卡片 12 / 分组 10 / 控件 8；阴影仅一层浅投影（card token），禁多层堆叠
动效 仅功能性过渡：状态点变色 150ms、面板展开 200ms ease-out、进度条 width 过渡；禁装饰动效与图表动画

深色模式：整表 token 翻转，组件零改动；跟随系统 + 手动覆盖（设置内三档：跟随/浅/深）。

1. 全局框架 MVP 必须

布局结构

左侧 220px 固定侧栏 + 右侧内容区（min 720px，1280–2560 自适应；侧栏在 <1080px 折叠为图标栏 56px）。

  • 侧栏（bg-sidebar，无边框，右侧 hairline）：顶部 applift logo 字标；导航项：状态驾驶舱（首屏/默认）、项目、发版（子项：Beta 向导 / Release 向导二期）、凭据二期、构建占位（灰置，标「规划中」）、底部：设置 ⚙、深浅色切换。
  • 侧栏徽标：驾驶舱项右侧数字徽标 = 未读状态变更数（与通知中心联动，点开即清）。
  • 内容区顶部 52px 工具条：页面标题 + 右侧「未读变更」铃铛按钮（含红点计数）+ 全局手动刷新。

信息层级

一级导航 = 功能域；页面内靠「分组卡片 + 组标题」分层，不用嵌套边框。错误横幅为唯一全局浮层，吸附在工具条下方。

组件清单（全局）

侧栏导航项（icon+label+badge）、工具条、铃铛+红点、刷新按钮（旋转 150ms×2 表示进行中）、错误横幅、通知下拉面板、Toast（右下角，自动消失 4s，错误态常驻可关闭）、四态骨架组件（Skeleton 行）、状态徽章 StatusBadge（色点+文字，全系统唯一状态表达）、新鲜度戳 FreshnessLabel（相对时间 + 超阈值变 stale 灰并加「·旧」）。

四态设计（全局元素）

  • 正常：侧栏徽标 = 0 时隐藏；铃铛无红点。
  • 加载：路由切换时内容区整体 Skeleton（驾驶舱用行级骨架，见 §3）；全局刷新按钮旋转。
  • 错误：错误横幅（rejected 底 8% 透明度、左侧红条、标题+一行原因+「去处理」按钮）。凭据缺失类错误横幅文案带渠道名，按钮跳「凭据管理」（一期无此页则跳设置内凭据说明 + 复制 ~/.applift/credentials.toml 路径按钮）。横幅可手动收起，凭据类收起后铃铛下保留一条置顶。
  • 空：无项目时侧栏保留全部导航；各页空态见各节。

交互说明

键盘：⌘R 全局刷新、⌘K 快速跳项目（一期可降级为不实现，结构预留）。通知面板从铃铛向下弹出（200ms），点击条目跳驾驶舱并高亮对应格子 1.5s。后台轮询由 UI 层调度：前台 5min / 后台可调（见 §5），每次轮询后仅状态点/徽章做 150ms 色彩过渡，无整页刷新。

2. 项目列表 MVP 必须

布局结构

页面标题「项目」+ 右上「添加项目」主按钮；下方项目卡片列表（每卡全宽，高约 88px）。卡片布局：左 40px 平台图标（Android/iOS/Harmony 系统感单色图标）｜中：项目名（15px semibold）+ 路径（mono 12.5px secondary，超长中间省略）+ 平台标签｜右：该项目渠道覆盖数「8 渠道」+ 最新版本号 + 状态摘要（绿点“全部正常”/红点“1 渠道被拒”/灰点“未同步”）+ 「···」菜单（打开目录 / 在驾驶舱中查看 / 移除）。

信息层级

名称 > 状态摘要 > 版本 > 路径。列表按名称排序，置顶支持拖拽（P2，一期按名称即可）。

组件清单

项目卡、添加按钮、添加抽屉（Sheet 从右滑入 420px：路径输入框 + 「校验目录」按钮 + 校验结果区 + 平台自动识别结果（识别失败可手选）+ 「扫描本机目录建议」链接——一期只展示建议列表条目（最近修改含 build 输出的工程目录），点击即回填路径）、空态组件、不可用态卡片、确认移除对话框。

四态设计

  • 正常：卡片如上；hover 150ms 底色加深 3%，点击整卡进入驾驶舱并定位该项目行。
  • 加载：初次进入 3 行骨架卡；「校验目录」点击后按钮内联 spinner + 结果区「校验中…」。
  • 错误：①路径校验失败：输入框下方红字原因（目录不存在 / 未识别到平台特征（无 build.gradle·xcodeproj·hvigor）／已是其他项目的子目录）；②项目不可用态：目录被移走后，卡片降级——状态摘要处显示灰底标签「目录不可用」+ 「重新校验」链接，卡片操作仅保留编辑路径与移除，不进入驾驶舱。
  • 空：列表区居中插图区（仅一个 app 图形 + 文案「还没有项目」+ 说明「添加本地使用 applift 的工程，统一查看各渠道审核状态」+ 主按钮「添加项目」+ 次按钮「扫描本机目录」）。

交互说明

校验为失焦+手动双触发；识别平台后回显三选徽章；移除需确认（对话框说明仅移除监控，不动工程文件）。所有写操作成功用 Toast 反馈。

3. 状态驾驶舱 MVP 必须（首屏 · 核心）

布局结构

三段自上而下：

  1. 摘要条（高 64px，无卡片的横向分组）：N 项目 · M 渠道监控 ｜ 本周变更 X 次 ｜ 异常 Y（被拒/错误合计，红字，点击过滤）｜「手动刷新」按钮 + 全局 FreshnessLabel（「全部数据更新于 3 分钟前」）。
  2. 过滤器行：项目筛选（多选 chips）、平台筛选（全部/Android/iOS/Harmony）、状态筛选（全部/审核中/被拒/已上线/旧数据）、右侧紧凑/舒适密度切换。
  3. 项目 × 渠道矩阵：按项目分组的表格。每组 = 组头（项目名+路径+平台图标+该项目新鲜度）+ 一行渠道格子。列 = 10 渠道固定列序（ASC/AGC/华为/小米/OPPO/vivo/荣耀/谷歌/蒲公英/应用宝），列头 sticky；该项目不适用的渠道显示淡「–」格。每格内容：StatusBadge（状态色点+状态词）+ 版本号（mono 12px）+ 相对时间（超阈值灰字加「·旧」）。被拒格：点变红底 8%，右上角红色小三角叹号。

格子即交互单元：单击 = 立即刷新该渠道（聚焦即刷新也作用于行/格 hover 停留 800ms 的惰性刷新，仅前台）；点击被拒格右侧展开行内详情条（最近被拒原因摘要 + 「查看变更历史」+ 「复制原因」）；每格 hover 出现「↻」迷你刷新。

信息层级

状态色点是第一视觉层（整页唯一彩色饱和元素），版本第二，时间第三。矩阵行高 56px，格子间靠 8px 留白分隔，不画格线。

组件清单

摘要条、过滤器 chips、矩阵表（sticky 列头 + 组头）、StatusBadge（状态枚举：待提交/已提交/审核中/被拒/READY_FOR_SALE/已上线/错误/未知——色映射：pending 琥珀、rejected/错误 红、READY_FOR_SALE/已上线 绿、待提交 灰、未知 灰问号）、FreshnessLabel、格子内联刷新、被拒详情展开条、跃迁高亮（状态刚变化 60s 内格子左侧 2px accent 竖条渐隐）。

四态设计

  • 正常：如上；数据新鲜度 = 距 fetchedAt 相对时间；阈值（默认 15min）后转 stale 灰并计入摘要「旧数据」。
  • 加载：矩阵区 5 行骨架（灰块 88% 透明度脉动，周期 1.2s）；已有数据的手动刷新期间格子内容保持旧值 + 格子右上 8px spinner，不闪骨架。
  • 错误：单渠道错误 → 格子显示红底「错误」徽章 + hover tooltip 一行原因（凭据过期 / 网络失败 / 解析失败分类文案）；整页加载失败 → 矩阵区错误占位（图标+「加载失败」+原因+「重试」）；部分渠道凭据缺失 → 全局错误横幅（§1）+ 对应格子灰「未配置」。
  • 空：无项目 → 居中空态「先添加项目，才能看到渠道状态」+「去添加项目」；有项目但全部未同步 → 矩阵显示组头 + 每格「未同步」灰字 + 摘要区「立即同步」按钮。

交互说明

前台 5 分钟轮询（不可在此页关闭）；手动刷新按钮刷新当前过滤范围；被拒出现时：格子红色态 + 通知中心新条目 + 系统通知（一期 webui 用浏览器 Notification，需授权引导一次性弹层）；READY_FOR_SALE 跃迁同理绿色通知。列在 <1280px 出现横向滚动（列头 sticky），密度「紧凑」模式行高 44px 隐藏版本号只留状态点。

4. 发版向导 · Beta 链路 MVP 必须

布局结构

居中 720px 单列分步向导，顶部步骤指示（1 预检 → 2 确认 → 3 执行 → 4 结果），当前步 accent，已完成绿点。左上「项目/目标」上下文条固定显示（项目名 · 平台 · 当前版本 → 目标版本）。

信息层级与各步内容

  • 第 1 步 dry-run 预检：选择项目与 profile 后自动执行 dry-run，展示判定预览——分组列表：将执行的动作（stages 顺序：构建检查→产物→上传→提审，每条 = stage 名 + 将作用的渠道 chips）；⚠ 影响项（将覆盖的 build 号、将打/补的 tag、不满足的前置条件）；✓ 通过项（灰字折叠，默认收起）。底部主按钮「进入确认」在预检有阻断项时禁用并说明原因。
  • 第 2 步 确认：投递方式区——每渠道一行：渠道名 + 默认推荐投递方式（来自 profile，如「API 直传」/「网页手动」）+ 下拉可改选；「全部使用推荐」链接一键还原。下方确认清单（复述第 1 步摘要 3 行内）+ 需勾选的确认框（仅当存在覆盖性动作时出现）。主按钮「开始发版」（强调色）+ 次按钮「返回」。
  • 第 3 步 执行：按 stage 分组的进度区，每 stage 一行：stage 名 + 状态点 + 聚合进度条；展开 stage 见每渠道子进度条（细 4px）+ 当前动作文案（如「上传 qy-driver.ipa → ASC」）。下方日志面板（等宽字体，默认折叠为 3 行高，可展开至 40vh，支持按渠道过滤 tab + 自动滚底开关 + 「复制日志」）。
  • 第 4 步 结果：结果摘要卡（成功绿/部分成功琥珀/失败红）+ 各渠道结果列表（状态+版本+渠道单号链接）+ 操作：失败渠道「重试失败项」/ 全部「完成」返回驾驶舱。

组件清单

步骤指示器、上下文条、预检分组列表、折叠组、渠道行（含下拉）、进度条（stage 粗/渠道细两级）、日志面板、结果卡、重试按钮。

四态设计

  • 正常：逐步推进；stage 完成即刻绿点 + 下一 stage 展开动画 200ms。
  • 加载：第 1 步 dry-run 期间显示预检骨架（分组标题 + 3 行灰块）+ 顶部「dry-run 执行中…」；第 3 步各进度条 indeterminate 模式（低幅往复）直至该步骤有确定进度。
  • 错误：第 1 步 dry-run 失败 → 预检区红色错误条 + 原因 + 「重试 dry-run」；第 3 步某渠道失败 → 该渠道子条变红 + 日志自动滚动到错误行并高亮，stage 聚合条显示「3/5」，不中断其他渠道（可继续）；确认超时态（上传凭据临时失效等等待用户介入）→ 出现行内「等待处理」横条 + 「跳过该渠道」/「重试」双选，向导整体暂停计时显示。
  • 空：无项目进入向导 → 空态引导去添加项目；第 2 步若某渠道凭据缺失，该渠道行显示灰「未配置凭据」+ 「去设置」链接，默认不勾选参与发版。

交互说明

第 3 步进行中关闭页面需确认（对话框：后台继续/取消发版——后台继续依赖 CLI 进程，一期若 UI 与进程同生命周期则仅「取消发版」并说明）；「取消」按钮在执行中常驻右上（次要红色），点击二次确认。结果页部分成功时同时给「重试失败项」（仅重跑失败渠道，跳过已完成 stage-after 判定）。

5. 应用设置 MVP 必须

布局结构

左锚点子导航（通用 / 通知 / 凭据说明二期 / 外观 / 高级）+ 右侧分组卡片表单。

内容与层级

  • 通用：数据同步组——前台轮询间隔（步进选择 1/2/5/10/30 分钟，下限提示「为保证渠道配额，最短 1 分钟」）、后台轮询开关 + 间隔（最短 30 分钟）、单渠道手动刷新节流说明文字；启动组——启动时打开页面（驾驶舱/项目）。
  • 通知：通知偏好——按事件类型开关（被拒 / READY_FOR_SALE / 发版完成 / 错误），每类可选站内+系统双通道（系统通道带「授权浏览器通知」按钮态）；免打扰时段（时间范围选择）。
  • 外观：主题三档（跟随系统/浅色/深色）实时切换 data-theme；密度默认值。
  • 高级：数据保留天数、日志级别、重置确认对话框。

四态

  • 正常：表单即时保存（改后 500ms 防抖），行尾短暂「已保存 ✓」。
  • 加载：进入时表单骨架；保存中按钮 spinner。
  • 错误：保存失败行内红字 + 「重试」，不整页报错；主题切换失败回滚并 Toast。
  • 空：不适用（设置恒有默认值；通知系统通道未授权时显示引导态而非空）。

6. 发版向导 · Release 完整链路 二期

复用 §4 向导骨架（同步骤指示/上下文条/进度/日志组件），差异点：

  • 第 1 步预检增加：多渠道提审矩阵预览（渠道 × 将提交的版本/备注/分阶段发布比例）；tag 补打判定项（「tag v3.2.1 已存在，将跳过 / 不存在，将创建」）。
  • 第 2 步确认增加：分阶段发布比例每渠道可调；生产发布确认框为强制（红色警示文案复述覆盖范围）。
  • 第 4 步结果增加：tag 补打结果组（每渠道打 tag 成功/跳过/失败 + commit hash mono 展示）。
  • 四态沿用 §4；新增超时态细分：提审接口排队超时 → 行内「渠道侧排队中，已转为后台跟踪，可在驾驶舱看结果」提示。

7. 凭据管理 二期

布局结构

单列分组列表，按渠道分组（ASC / AGC / 华为 / … 蒲公英 / 应用宝），每组显示该渠道全部凭据字段行。顶部路径条：~/.applift/credentials.toml + 「在外部编辑器打开」+ 「重新加载」。

信息层级

渠道组头（图标+名称+配置状态徽章：已配置/缺失/格式错误）> 字段行（字段名 + 脱敏值如 sk_••••••3f9a + 编辑/显示按钮）。

四态

  • 正常：脱敏显示；hover 字段行出现「👁 显示明文」（点击要求本机确认，5s 后自动恢复脱敏）与「✎ 编辑」（行内变输入框，保存写回 toml）。
  • 加载：进入时每组骨架；重新加载时顶部进度条。
  • 错误：toml 解析失败 → 页面顶部错误横幅带行号/原因 + 「在外部编辑器打开修复」；缺失项 → 对应渠道组状态徽章「缺失」+ 字段行灰底虚线框「未配置」+ 「查看配置示例」折叠；写入失败（权限）→ 行内红字 + 复制手动配置指引。
  • 空：文件不存在 → 居中空态「尚未配置任何凭据」+ 说明 + 「创建配置文件」按钮（写入模板）。

交互

与驾驶舱联动：某渠道凭据缺失时，驾驶舱错误横幅「去处理」直达该渠道组锚点并高亮。

8. Tauri 壳 · macOS 状态栏 Popup 二期

布局结构

固定 360×480。自上而下：① 顶部 40px：标题「applift」+ 全局新鲜度（相对时间）+ 设置齿轮；② 状态摘要条（一行三段：正常 N · 审核中 M · 异常 K，异常红字）；③ 项目概览列表（主体，每行 56px：平台图标 + 项目名 + 状态点簇（最多显示 5 个渠道点，余 +N）+ 项目新鲜度；点击行展开该项目的渠道迷你行（渠道缩写 + 状态点 + 版本），再点击收起）；④ 底部固定操作区（高 56px，hairline 上边）：「发版」快捷入口（弹出发版目标选择：项目→beta/release）+ 「打开完整界面」（唤起 webui 主窗口）。

信息层级

状态点簇是第一视觉；文本最小 12px；深浅跟随系统（menu bar popup 默认无独立主题开关）。

组件清单

摘要行、项目行（可展开）、渠道点簇、底部操作条、跃迁角标（自上次打开 popup 后有变化的项目行右上 accent 圆点，打开 popup 3s 后清除）。

四态

  • 正常：如上；点击状态点簇任意点 = 直接展开该渠道详情行。
  • 加载：打开 popup 首帧显示上次缓存数据 + 顶部细进度条，数据到达后无感替换（禁止闪骨架）。
  • 错误：某渠道错误 → 红点；整页数据不可用 → 摘要条位置显示「数据不可用 · 重试」；凭据缺失 → 底部操作条上方 32px 提示条「N 个渠道未配置凭据」点击跳凭据页（打开主窗口）。
  • 空：无项目 → 居中「添加项目后在此查看状态」+「打开完整界面」；后台服务未启动 → 「CLI 未运行」说明 + 启动指引。

native 通知样式

macOS 系统通知：标题「qy-driver · ASC」+ 正文「状态变更为：被拒」+ 操作按钮「查看」「忽略」；点击「查看」打开 popup 并定位该项目展开行。通知事件类型与免打扰遵循 §5 通知偏好。

9. 构建接管（占位）占位

不细化，仅布局预留：侧栏「构建」入口灰置；进入后为占位页（说明文案「构建触发与产物管理规划中」）。预留信息架构：构建任务列表（项目×任务×状态）→ 任务详情（日志/产物 tab）→ 产物管理（版本×产物×分发目标）。设计上沿用驾驶舱的「摘要条 + 过滤行 + 列表」骨架与 StatusBadge，保证未来扩展视觉同构。

附 D · 场景适配与一致性结论

  • 管理/工具型定位：全部页面沿用「摘要条→过滤→列表/矩阵」骨架与同一 StatusBadge/FreshnessLabel 词汇，状态色是唯一饱和色，信息密度高但三层灰阶 + 留白分组保持克制，符合 Apple 风格且贯穿一致。
  • 强光/单手等移动场景：非目标场景（桌面工具），popup 已按 glanceable 原则压缩为「点簇一眼读态」，webui 最小支持 1280px，不承诺移动端布局。
  • 深浅模式：token 全量双份，状态色暗色下提亮（pending 琥珀在暗底改亮金 #E0A020、rejected #FF6B5E）保证 4.5:1 对比。
  • MVP 边界复查：§1–§5 为一期必须；§6–§8 二期（§6/§7 与 §4/驾驶舱组件复用率高，无新增组件族）；§9 仅侧栏灰置入口 + 占位页。
